# PiNAS v1.0.6 — Overview health and diagnostics (test candidate)

**Development/test milestone only.** This branch stays unmerged pending Raspberry Pi hardware checks. No official release or version tag is created.

## Changes
- Remove the Load average (1 / 5 / 15 minute) row from System Health and stop calculating it in the hardware payload.
- Remove the separate Disk health section from Storage. Existing disk management and its safety warnings remain unchanged.
- Display each visible NAS drive's SMART health and temperature directly beneath its usage bar in Overview → Storage at a glance.
- Preserve the existing authenticated, read-only SMART API. Match SMART values to drives by their device path, not by potentially duplicated model names.
- Check disk health when Overview opens, with an on-demand **Check disk health** button for refresh. No recurring SMART polling or new daemon.
- Where SMART Tools are missing or an adapter does not report health/temperature, indicate that clearly rather than inventing a healthy state.

## Raspberry Pi test checklist
1. Update v1.0.5 to this candidate and verify existing disks, shares, user login and RAID status remain intact.
2. Overview → System Health no longer shows load average; system model, OS, kernel, uptime and throttling still work.
3. Overview → Storage at a glance shows each drive's usage bar, health state and temperature in the same entry.
4. On the Storage page, confirm disk management remains available but the separate Disk health card is gone.
5. With smartmontools installed and a compatible disk/USB adapter, compare Overview values with `sudo smartctl -j -H -A /dev/sdX` on a disposable/test disk.
6. Check a drive or USB adapter that cannot provide SMART values; verify PiNAS shows an unavailable value without an incorrect healthy status.
7. Verify refresh on Overview; normal background UI updates do not repeatedly invoke SMART.
8. Confirm the interface and service remain responsive on Raspberry Pi 3B/3B+ hardware.

MiniDLNA reintroduction remains separate pending a clean test installation and diagnosis of the previous package installation error.
