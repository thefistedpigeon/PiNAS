# PiNAS v1.0.5 — Storage safety (unreleased test milestone)

The v1.0.5 branch is **not merged** and this is **not a published release**. The intended next public release remains v1.0.6 after testing.

## Changes
- Read-only status for persistent **PiNAS-managed** UUID mounts: mounted, missing drive, present but unmounted, or unexpected filesystem at the target.
- Prominent alerts on Overview, Storage, and RAID pages when a configured PiNAS data mount is unhealthy or a detected mdadm array is degraded.
- Fresh block-device discovery directly before privileged filesystem adoption, to reject a removed, read-only, unsupported, or no-longer-eligible device even if the browser previously displayed it.
- Preserve the existing independent privileged storage-helper checks against root/system storage, unsupported devices, incorrect mounts and unsafe fstab edits.
- No destructive formatting, partitioning or RAID creation is enabled in this milestone.

## Safety and limits
The new status reader inspects only fstab entries explicitly tagged `# PiNAS managed` whose mount path is `/mnt/pinas/<UUID>`. Custom administrator-created mounts are not monitored. Mount status is observed when hardware status is requested; no new service, persistent polling or automatic mount/repair is introduced. Incomplete or previously configured fstab entries might require manual review.

If a drive is missing, **do not** write new files to its expected mount directory. Reconnect and verify the physical disk and UUID before attempting recovery. A degraded RAID array is not a backup and should be addressed before further disk changes.

## Hardware test plan
1. Install this branch on a disposable PiNAS installation and confirm storage, users and SMB shares still work.
2. Confirm an existing PiNAS-created UUID mount is reported healthy, with no warnings.
3. Safely stop SMB I/O, unmount a test data disk, then verify an **Not mounted** warning appears. Restore it and verify the alert clears.
4. With a disposable USB disk only, disconnect and refresh; verify the status becomes **Device missing**; reconnect and remount before continuing.
5. Confirm a disk removed after opening the Storage page cannot be adopted using the stale browser selection.
6. Verify `/`, boot storage, swap, and unrelated fstab entries remain excluded; no destructive actions have become available.
7. If using mdadm, verify the read-only array display and degraded-warning logic without intentionally degrading a production array.
8. Reboot and confirm data mounts and SMB shares return normally.

MiniDLNA is intentionally excluded pending the rebuilt test Pi.
