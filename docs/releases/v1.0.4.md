# PiNAS v1.0.4 — Reliability & Recovery (test candidate, not published)

This is a **development milestone only**. It is not merged into `main` and does not create an official release. The intended next public release remains v1.0.6 after additional testing and iteration.

## Changes

- **Configuration recovery:** Admin-authenticated JSON download containing safe device preferences, NAS user display names and a read-only share/user inventory. No stored administrator password hashes, SMB secrets, TLS private keys, login background image or file data are exported.
- **Settings restore:** Re-apply only validated theme, font, CPU monitoring, session timeout and display-name values after administrator re-authentication and explicit confirmation.
- **Installer safeguard:** During command-line installations or upgrades, validate the standalone installer first, preserve the previous `pinas.py`, stage the new file in the same directory and atomically replace it. Restore the prior file if module extraction fails.
- **Release process:** The old v1.0.3 publishing workflow no longer runs on ordinary pushes; v1.0.4 remains a separate, unmerged candidate.
- **Documentation and tests:** Updated README and added security and recovery regression checks.

## Important limitations

The JSON file is **not** a complete disaster-recovery archive. It does not recreate Samba accounts, passwords, SMB shares, RAID, disk mounts, filesystem contents, operating system or packages. The share inventory is informational only. Keep external backups of all important NAS files and separate records of your disk layout.

The command-line installer retains a prior application file but does not provide a full transactional rollback for OS package installation, systemd or sudoers configuration. Test restoration on a disposable NAS before relying on it.

## Hardware test checklist

1. Fresh Raspberry Pi OS Lite install; apply this candidate using the installer and verify PiNAS starts.
2. Create a NAS user, configure a mounted disk and SMB share, and check read/write and standard-user WebUI access.
3. From administrator Settings, download the JSON backup and verify it does not contain passwords or certificates.
4. Change theme/font/CPU monitoring preferences, restore the JSON and confirm only supported preferences and display names change.
5. Verify accounts, SMB permissions, shares, mounts and files remain unchanged after restore.
6. Test the update from v1.0.3 to v1.0.4 and reboot the Pi; confirm service and shares survive. Prefer a clean spare installation, never your only copy of data.
7. Test an intentionally invalid restore file and incorrect admin password to ensure both are rejected.
8. Verify user logoff, update reboot controls and default avatar still work.

MiniDLNA is intentionally out of scope while the test device is rebuilt.
