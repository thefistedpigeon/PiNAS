# PiNAS v1.0.3 — On-demand reboot after updates and user avatar fallback

## System updates

- PiNAS shows the **Reboot PiNAS** control on **System Updates** only when the OS reports `/run/reboot-required`.
- The control stays hidden when no reboot is required or while an APT operation is running.
- The action is limited to an authenticated administrator with a valid CSRF token and current administrator password.
- The root update helper independently rechecks `/run/reboot-required` before scheduling a systemd reboot with a 10-second delay, allowing the web request to respond.
- Automatic updates never trigger an automatic reboot. Regular NAS users cannot reboot the appliance.

**Caution:** A reboot temporarily disconnects SMB shares and the PiNAS interface. On-device reboot testing is required before merging.

## NAS user avatar

- The supplied profile SVG appears by default in the standard-user header and profile settings preview.
- Uploaded profile pictures continue to take precedence.
- Removing the custom profile image restores the default SVG immediately.

## Verification

Run `python3 tools/build_release.py --check` and `python3 -m unittest discover -s tests -v`. The additional tests exercise administrator password, session/CSRF, concurrent-update and reboot-marker guards without actually rebooting a host.
