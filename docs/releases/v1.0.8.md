# PiNAS v1.0.8 — Protected Wipe Disk and Format Disk

**Official release. Destructive operations can permanently destroy data. Use only on verified, backed-up drives.** The previous version had Wipe Disk and Format Disk disabled; this release restores them through a dedicated, narrowly scoped root-owned helper and confirmation card. Automated tests have passed; test drive behaviour carefully on your own hardware before using it with important data.

## Changes inherited from v1.0.7
PiNAS v1.0.8 also includes the v1.0.7 improvements, which were merged to `main` but not published as a separate official release:
- Separate SQLite history of manual and scheduled APT upgrades, retaining 6 or 12 months of records.
- Health monitoring of the automatic-update timer and one-shot service on System Updates and Overview.
- Administrator-authorised recovery actions for failed automatic-update units.
- Consistent SVG icons, labels, and hover styling on Storage, RAID, and Updates buttons.

## Available actions
- **Wipe Disk:** Removes partition tables and filesystem signatures from the selected entire physical disk and its detected partitions. This is a *quick wipe*, **not** a secure overwrite. Remnant user data may be recoverable. This operation does not mount, adopt or format the disk afterward.
- **Format Disk:** Removes existing filesystem signatures and partition tables, then creates one filesystem directly on the entire disk; choose **EXT4**, **XFS** or **Btrfs**. Disk mounting and share creation remain separate operations. The existing PiNAS discovery and adoption helper supports filesystems directly on whole disks.
- **Mount Disk** and existing non-destructive adoption remain unchanged.

## High-risk confirmation
Each action opens a modal card identifying the disk and showing a clear data-loss warning. The user must separately check **Yes, I understand** and supply the **current administrator password**. Confirmation is independently validated server-side with an authenticated administrator session and CSRF token; the root-owned helper then repeats disk eligibility checks.

## Protected targets / safety
The privileged helper refuses operations on:
- root/boot system storage, mounted disks or mounted partitions;
- swap devices, virtual/loop devices, read-only drives and small unsupported disks;
- RAID, LVM, encryption and other nested device layouts, and devices with active holders;
- disks with persistent fstab references by device, UUID, PARTUUID, LABEL or PARTLABEL;
- devices not identifiable as a single whole physical disk, unknown mount topologies, and devices that change between checks.

All device paths are fixed direct `/dev/...` names. Helper commands use fixed argument arrays and explicitly allowed filesystem tools, never a shell. There is a system-wide lock for PiNAS destructive actions. The helper is installed by both fresh installs and browser-based upgrades. Existing share definitions and fstab records are not removed automatically; remove obsolete configuration **manually and with backups** before attempting to repurpose a previously managed drive.

## Test plan (disposable drive only)
1. Install v1.0.8 on a spare Raspberry Pi using the uploaded `pinas.py`. Verify the existing PiNAS settings, mounts and shares remain accessible.
2. Open Storage → Manage Disk on an **empty disposable USB drive**. Verify Wipe/Format buttons are visible and have standard hover styling.
3. Open each high-risk confirmation card. Verify that Cancel, Escape and outside click leave disk data unchanged, and that **Confirm** stays disabled until both Yes and a password are entered.
4. Use an incorrect admin password; ensure the operation is rejected without modifying the drive.
5. Test both Wipe and Format with the correct password on a *disposable* drive. Verify all three filesystem choices independently if practical, and that mounting is still a separate action.
6. Ensure the system SD/boot drive is not offered and that mounted, RAID or configured data drives are refused. Do not intentionally test erasure against live storage.
7. Disconnect and reconnect a disposable drive to ensure a stale Storage UI state does not bypass server-side validation.
8. Run the previous Storage adoption and NAS share tests to ensure unchanged behaviour.

## Limitations
- This is not a secure-erase utility; removing signatures does not overwrite every data block.
- Formatting currently creates one filesystem directly on the whole disk, without creating a GPT partition. Linux and PiNAS support this layout, but other systems might not recognise it as a conventional partitioned drive.
- Formatting can fail on hardware or filesystems with unsupported block sizes, insufficient capacity or missing formatting tools. Prior metadata may already be erased if a later formatter step fails.
- Never use these actions on any mounted filesystem, active NAS share, root/boot disk, or a drive listed in `/etc/fstab`.
