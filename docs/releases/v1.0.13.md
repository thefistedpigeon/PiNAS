# PiNAS v1.0.13 — Storage Media Breakdown & Share ACL Inheritance (development candidate)

This candidate focuses on the Overview storage display and newly created SMB folders.

## Overview: storage by media type

Each mounted NAS disk is shown with a segmented space-used bar and key:

- **Video:** AVI, MP4, MKV, MOV, M4V, MPG/MPEG, WebM and similar extensions.
- **Pictures:** JPG/JPEG, PNG, BMP, SVG, GIF, WebP, TIFF, HEIC and similar extensions.
- **Music:** MP3, WAV, AAC, FLAC, OGG, M4A, Opus and similar extensions.
- **Other / filesystem:** all remaining disk usage, including unrelated file types, metadata and unclassified files.
- **Free:** available storage.

The media scanner is **on demand**, triggered when the Overview is first opened, with a 30-minute cached result and a manual *Rescan media types* button. It runs in a low-frequency background worker and never opens a file's contents, follows symlinks or scans OS partitions. It uses allocated-block sizes, so compression, sparse files, hardlinks and filesystem metadata can make the values approximate. A first scan of a very large library may take time; it does not block the PiNAS HTTP interface.

## Samba share permissions

New and edited PiNAS shares now enable `inherit acls = yes`, letting Samba propagate the existing default POSIX ACL from the share root. The share editing helper also fixes the old operation ordering that called `chmod 0700` *after* creating named-user ACLs: the chmod could zero the ACL mask and deny those users access.

### Repair existing folders

The **Repair access** button for a PiNAS-managed share is administrator-password protected. It:

1. Checks that the share matches the managed PiNAS database and its expected mounted NAS volume.
2. Refuses any share with nested mount points.
3. Reapplies the **currently configured named-user ACL rights** to files and folders on that one share, and default directory ACLs for future entries.
4. Preserves ownership, unrelated ACL entries and files. It does **not** run `chmod -R`, open public access or modify another share.

Changing a share's user policy still requires using **Edit share**. Repair is intended for fixing access to existing subfolders and cannot itself revoke every legacy custom ACL. Existing files in very large directories may take time to process.

## Validation before promotion

Tests cover file-extension classification, real temporary-folder scan and symlink exclusion, background scan/route wiring, Samba ACL inheritance and the share repair action. Real-device tests: create nested folders over SMB and the web interface, write to them as allowed NAS users, confirm denied users stay denied, test private home shares, and compare file breakdown against a sampled disk. Check Pi 3B scan performance on large libraries.
