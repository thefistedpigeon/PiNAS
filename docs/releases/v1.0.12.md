# PiNAS v1.0.12 — Guided MiniDLNA Media Library (release candidate)

This candidate extends the optional Media Server introduced in v1.0.11.

## First-run media library setup

After MiniDLNA is installed, the Media Server page offers a standard library wizard.

1. Choose one of the mounted, persistent, writable PiNAS data volumes.
2. Authenticate with the PiNAS administrator password.
3. PiNAS creates `pinas-media` on that volume, with `Movies`, `Television`, `Music`, and `Pictures` subfolders.
4. MiniDLNA media_dir is configured as `V,Movies`, `V,Television`, `A,Music`, and `P,Pictures` (full absolute paths), and inotify is enabled.
5. PiNAS restarts MiniDLNA to apply the new library.

The same wizard is available later. If a MiniDLNA media_dir list already exists, PiNAS warns that the service's configured library entries will be replaced. It **does not delete the old folders or their media files**.

Only folders that are missing are created. Existing directories, files and ownership are preserved. On configuration failure, PiNAS restores the previous config and only removes newly created directories if they remain empty. The action is limited to mounted /mnt/pinas data volumes; system disks, unmounted filesystems and read-only volumes are excluded.

**Important:** The generated folders are readable by MiniDLNA, but do not automatically become an SMB share. This avoids silently exposing media to every NAS account or changing existing share access rules. An administrator can subsequently share a media folder through the normal Shares workflow.

## MiniDLNA configuration usability

- Fields display existing explicit values where available, rather than overwriting them on initial load.
- Absent values show useful package defaults or labelled recommended starting values.
- Root container and TiVo discovery use dropdowns with documented choices.
- Input hints describe networking, server identity, scanning, logging, subtitle and thumbnail settings.
- Numeric inputs include validated bounds; optional blank numeric inputs are not sent as zero.
- Existing installation, start/stop, index rebuild, manual folder entry and explicit ACL grant remain available.

See the Debian manual for valid fields and defaults:
https://manpages.debian.org/unstable/minidlna/minidlna.conf.5.en.html

## Validation

Tests cover the four-folder provisioner, preservation of existing files, failure cleanup, API password gating and the standalone build. Device testing is required before release: perform initial MiniDLNA installation, disk selection, first-run setup, media playback with a DLNA client, a second idempotent setup, an offline-drive rejection and a browser-based PiNAS update.
