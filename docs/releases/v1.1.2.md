# PiNAS v1.1.2 — Quality of Life

Release date: 2026-11-07

## Updates in this release

### Overview service health
- Shorten the healthy automatic-update service status from `Last run succeeded or waiting for next schedule` to `Last run succeeded`. Existing failure, pending, and disabled states retain their distinct messages.

### Session timeout
- Respect the configured idle timeout (5, 10, 15, 30 or 60 minutes).
- Read-only polling, including the 10-second Overview/Storage/RAID refresh, no longer extends server sessions.
- Record actual user interaction (pointer, keyboard, wheel, scroll) and renew server sessions with a throttled, CSRF-protected heartbeat.
- Redirect automatically to login on inactivity or an expired authenticated request. Recalculate the browser and server timeout immediately when Settings are saved.

### Disk health
- Remove the manual Check disk health buttons from Overview and Storage.
- Run a nonblocking SMART probe automatically on entry to either page and every ten minutes while one of those pages remains open.
- Preserve the current health/temperature indicators, an in-flight guard against overlapping probes, and the existing smartctl standby protection (no deliberate wake-up).

### Update history
- Replace month-based retention choices with 1–52 weeks, defaulting to 12 weeks.
- Apply the range to the root-owned history-helper's validation and database pruning, as well as a read-side cutoff so legacy older entries disappear immediately when PiNAS is upgraded.
- Show each update as a collapsed, expandable date-only card. Expanded content lists recorded package names and the APT summary, with success/failure status visible on the collapsed card.
- Increase the update-history API page size to 500 records, sufficient for daily updates across a typical year.

## Upgrade and compatibility

The existing standalone `pinas.py` install and browser-based update workflow remain unchanged. The next successful APT history recording or a manual retention save physically prunes SQLite entries outside the selected week range. Old `update_history_months` settings are ignored, and saving a new selection removes the legacy preference.

No NAS disks, shares, RAID arrays, or Samba permissions are modified by the update. Font assets introduced in v1.1.1 remain self-hosted.

## Validation

GitHub Actions performs Python compile, generated bundle consistency, lint and full regression checks, including v1.1.2 tests for session renewal, retention, date-only history and automatic SMART checks. Validate session expiry and SMART compatibility on a real Raspberry Pi before installing broadly.
