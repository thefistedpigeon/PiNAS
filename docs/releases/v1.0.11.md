# PiNAS v1.0.11 — Media Server (development candidate)

**Unreleased.** Built on top of the v1.0.10 share-path/private-home feature.

## MiniDLNA / ReadyMedia

- Adds a dedicated **Media Server** navigation page.
- Detects installed MiniDLNA automatically and offers optional installation.
- Configures network/server identity, media libraries with optional A/V/P media type filters, inotify, discovery, compatibility, metadata, logging and connection settings.
- Start, stop, restart, routine restart-based scan and an explicitly confirmed rebuild that removes only the MiniDLNA media index from known package cache locations.
- Uses a dedicated root helper with a restricted PiNAS sudo rule; installation and changes require administrator-password confirmation.
- Preserves unmanaged configuration directives and comments. Failed service reloads restore the prior file.
- Existing media folders and share permissions are never altered automatically. Admins may deliberately grant the MiniDLNA service account read-only ACLs to a saved library path, including default read ACLs for new files.

## Security and permissions

DLNA clients cannot use PiNAS SMB authentication. Do not select private home shares unless you deliberately want them to be served to trusted DLNA clients. The minidlna service account needs read access to configured folders. This version never automatically rewrites filesystem permissions. The **Grant DLNA read access** action requires a separate administrator-password confirmation and may take some time on large folders.

The guided folder editor offers existing NAS shares as presets and accepts paths under mounted /mnt/pinas volumes only. Thumbnailed media options depend on build support. Other custom system settings in /etc/minidlna.conf are left intact.

## Validation

Automated tests cover installation wiring, helper compilation, input/path validation, configuration preservation/rollback, restricted ACL grants and bounded index rebuild. Test on a real Pi and DLNA client before promotion.
