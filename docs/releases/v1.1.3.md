# PiNAS v1.1.3 — Update Logs & Share Management

Release date: 2026-11-07

## Download Logs (System Updates)
- Download all APT update events still available within the configured 1–52-week retention window from **System Updates → Installed update history → Download Logs**.
- UTF-8 text export includes generation date, retention, each run's date, automatic/manual origin, success/failure status, recorded packages, and the saved APT summary.
- Download requires an authenticated administrator session; server returns a fixed dated filename and `Cache-Control: no-store`. The export uses no remote dependencies.
- The read-side history query can return up to the 2,000-event SQLite history cap; the interactive view retains its current size and layout.

## Remove User (Users)
- Add **Remove User** with the supplied icon to NAS accounts and non-primary, non-current administrators.
- Require the exact username, explicit confirmation checkbox, and current administrator password.
- Removal of NAS users revokes Samba credentials and deletes only the managed Linux account, preserving all files and folders. It refuses deletion while any managed share still lists that account. Stop private home shares or edit access permissions first.
- Secondary admin removal deletes its PiNAS configuration identity; primary and current administrator accounts cannot be removed.
- Sessions belonging to removed users are invalidated.

## Stop Sharing and Delete Folder (Shares)
- Rename the non-destructive **Remove share** operation to **Stop Sharing**. It removes the managed SMB configuration but never deletes folders or file data.
- Add a **Delete Folder** button using the supplied folder-with-X icon. Explicit typing of the exact share name, an acknowledgement checkbox, and current administrator password are required.
- The root share broker independently checks the active managed share database, selected data device, persistent mount, protected share root, exact path, root ownership and nested mounts; it refuses symlinks or unexpected filesystem crossings.
- SMB sharing is stopped first, then `rm -rf --one-file-system -- <validated directory>` removes exactly that folder. No shell interpolation. If deletion fails after SMB removal, PiNAS reports a partial failure and does not re-share partially removed content.
- Deletion runs as a bounded asynchronous job so the browser request does not time out. **Permanent removal cannot be undone.**

## Upgrade/compatibility
- Version bumped to **1.1.3**. Installer and WebUI upgrade still use the standalone `pinas.py`.
- The privileged helper allowlist adds narrowly scoped account removal and managed share-folder deletion. No extra Python dependencies are introduced.
- The fonts, 1.1.2 session/SMART/retention improvements and existing media-server features remain.

## Manual validation on a test Pi
1. Export the APT history with 1, 12 and 52 weeks selected and compare against visible retained runs.
2. Stop sharing a disposable test share; verify files remain on disk and SMB no longer exposes the share.
3. Delete a separate **disposable** test share folder; confirm the share and its files disappear, but other shares and disk data remain.
4. Attempt deletion of a share containing a mounted nested filesystem; confirm refusal.
5. Remove a NAS account assigned to a share; expect refusal. Remove the share permission, retry, and verify its Samba and Linux login are revoked without deleting data.
6. Try removing the primary/current administrator; expect refusal.
7. Test on a Pi 3B with a large folder and ensure the asynchronous status completes or reports errors clearly.

**Status:** Proposed release for review and real-device testing. Recursive deletion is irreversible; do not validate against important files.
