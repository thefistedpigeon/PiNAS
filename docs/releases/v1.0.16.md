# PiNAS v1.0.16 — Browser Uploads for MiniDLNA (development candidate)

Adds administrator-only media uploads directly from PiNAS **Applications-free Media Server** page.

## Workflow

After installing MiniDLNA and saving or creating its media folders, an administrator can select **Upload media** beside **Grant DLNA read access** on each configured folder. The browser presents a multi-file picker, then requests the current administrator password before starting. A progress bar identifies the current file. Cancelling cleans up the current partial upload; successfully completed earlier files remain.

Supported upload types include typical video (MP4, MKV, AVI, MOV, MPEG, WebM), audio (MP3, FLAC, WAV, M4A, AAC, OGG), pictures (JPG, PNG, GIF, WebP, SVG, TIFF, HEIC) and subtitles (SRT, VTT, ASS, SSA, SUB, IDX). Each file must be nonempty and no larger than 100 GiB. The browser sends 384 KiB chunks without loading the entire file in memory. **Existing filenames are never overwritten.**

The privileged helper writes a private temporary file inside the destination folder and only publishes it after the expected number of bytes has arrived. It sets the file mode and a read-only MiniDLNA ACL on the completed upload. If MiniDLNA cannot traverse a configured folder, use **Grant DLNA read access** on that folder. The MiniDLNA service's inotify watcher can then discover uploaded files; **Restart scan** remains available when necessary.

## Privilege and safeguards

- Upload API is restricted to authenticated administrators, and the start request requires administrator password reauthentication.
- The helper only writes into folders explicitly listed in the current MiniDLNA configuration and on mounted PiNAS data volumes; it rejects symlinked paths and traversal.
- Filenames cannot contain path separators, control characters, dot-prefixes or unsupported extensions.
- Each upload receives an unpredictable transfer token; offsets and total file size are checked for every chunk.
- Temporary files are root-owned and mode 0600. Final publication is atomic and no-clobber via a hard link on the same filesystem; uploaded files are read-only to the MiniDLNA account.
- The browser-based PiNAS updater refreshes the new restricted media upload helper and sudoers entry, just like the CLI installer.
- This feature doesn't create Samba shares, alter existing media files, or expose private NAS user folders outside the MiniDLNA configuration.

## Before promotion

Automated tests cover extension restrictions, safe upload staging, chunk offsets, no overwrite, helper syntax, UI wiring and standalone build consistency. On a Raspberry Pi, test uploads of medium/large MP4 and MKV files, images, multi-file selection, interrupted uploads, unavailable space, and MiniDLNA playback. On devices with limited CPU and memory, large uploads may be slower due to per-chunk privileged-helper invocation.

**Status:** Draft release candidate pending real-device verification.
