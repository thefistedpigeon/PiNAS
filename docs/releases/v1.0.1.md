# PiNAS v1.0.1 — Code quality and visual consistency

Maintenance-only release, branched from v1.0.0. This release does not change NAS storage formats, share layouts, file data, or destructive-operation safeguards.

## Changes

- Consolidated light/dark design tokens and introduced shared spacing, button and table utilities.
- Removed obsolete colour-blind theme choices and custom accent inputs from public settings APIs, retaining compatibility with existing stored configuration.
- Standardised initial CPU-temperature colours using the same semantic theme tokens as refreshes.
- Centralised repeated calls to privileged NAS brokers and standardised installer helper/sudoers registration without expanding allowed commands.
- Removed obsolete prototype version terminology.
- Added CI verification and regression checks for generated-release synchronization and UI theme invariants.

## Validation

Run `python3 tools/build_release.py --check` and `python3 -m unittest discover -s tests -v`.
GitHub Actions checks pull requests for Python syntax, embedded JS syntax, and regressions.

## Upgrade guidance

Use the standalone `pinas.py` update file. Test the update on a non-production Raspberry Pi and retain a backup before promotion. Live hardware tests for storage, SMB permissions, updates, MiniDLNA, and responsive layouts are still required.

## Source reconciliation required before promotion

The GitHub `main` snapshot reviewed for this maintenance branch does not contain `NAS_MINIDLNA_HELPER` or `NAS_DESTRUCTIVE_HELPER`, despite RC-era tests referring to them. Those specific tests are skipped with explicit reasons, not counted as functional evidence. Before merging or installing this maintenance release, reconcile the source branch with the last Raspberry Pi build that was tested for MiniDLNA and storage-management features. This draft does not reintroduce missing features or claim to have tested them.
