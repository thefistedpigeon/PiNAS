# PiNAS v1.0.15 — Storage Diagnostics and Device Maintenance

**Status:** Development candidate. Do not merge until real Raspberry Pi tests confirm disk health, file-type scanning and administrator power control.

## Disk health

- SMART checks remain optional and on-demand, with a check button on Overview and Storage.
- Report Healthy, Warning, SMART available, Standby, Unsupported, Timed out or Unavailable, with available diagnostic context.
- Query with smartctl `-n standby`; USB-connected disks can retry using SAT bridge support without intentionally waking sleeping drives.
- Display temperature where the drive reports it. Some USB adapters and flash devices cannot return SMART status.

## File Type Scan

- The file-type scan, button and segmented visual now belong to the **Storage** page, under the selected mounted data disk. Overview retains a simple used/free bar.
- Each configured and persistently mounted PiNAS filesystem has its own **Scan file types** control and results.
- Scan only when explicitly requested; the browser can leave the page while the root helper continues its background scan.
- The root helper solves access-denied errors on root-owned SMB shares, without broadening filesystem permissions. It rejects arbitrary paths, symlinks, unmounted folders and traversal into other filesystems.
- Video, Pictures, Music, Other / filesystem and Free are shown with allocated size totals. Other includes nonmedia files and estimated filesystem overhead. Classification uses file extensions, not file content.
- Large scans may take time; the UI displays status, errors and skipped-directory counts. No separate persistent daemon or rapid polling of disk contents is installed.

## Administrator power controls

- Administrators get a Device maintenance action in the main header, with Restart PiNAS and Shut down PiNAS.
- A second dialog requires the current administrator password. The API independently checks administrator role, password, action and explicit confirmation.
- The restricted `pinas-power` broker schedules a fixed systemd reboot/poweroff in eight seconds so the browser can receive acknowledgement.
- Active file transfers and media playback may be interrupted. Reboot reconnects automatically; shutdown requires powering the Pi back on manually.

## Verification

CI verifies the generated standalone bundle, Python/JavaScript compilation, privileged helper syntax and regression tests. Real hardware tests should include sleeping USB HDDs, unsupported USB-SATA bridges, an ext4 data volume with private ACLs and known sample media, multi-drive layouts, browser updater helper refresh, and a real restart/shutdown.

**Note:** This candidate changes only PiNAS management code. It does not rewrite existing SMB ACLs, fstab mount entries, files or RAID configuration.
