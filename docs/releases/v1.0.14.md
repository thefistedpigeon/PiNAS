# PiNAS v1.0.14 — Hardening Candidate

**Status:** Draft pull request; not yet an official release. Review and on-device testing are required.

## Resource usage

- Config loading now uses an inode, mtime and size cache, preventing repeated multi-megabyte JSON parsing on CPU samples and the /api/state poll. Calls return independent copies so one request cannot mutate the cached configuration.
- APT upgrade listings are cached for 60 seconds. While a refresh or upgrade is running, /api/updates returns cached package data rather than invoking apt list for every 3-second poll.
- HTML page bytes are encoded once at application startup; routine /api/state and /api/pinas-build requests do not flood stderr logs.
- SMART queries use smartctl -n standby, avoiding waking standby hard disks for routine health inspection.

## Privilege and filesystem reliability

- Manual and scheduled apt upgrades use DEBIAN_FRONTEND=noninteractive and a 300-second dpkg lock wait.
- sudoers rules are staged, validated with mandatory visudo, then atomically installed. No sudoers policy is installed without validation.
- PiNAS Samba share create/edit/delete/migrate/repair operations are serialized with flock.
- Long-running MiniDLNA ACL grants, share permission repairs, web file copies and deletes return a session-scoped job ID. The browser polls the job's result, without prematurely timing out.
- Shared-folder listings use 200-entry pages and a Load more files control instead of silently stopping at 1,000.
- Downloads use one authenticated file broker and stream directly to the browser's native download manager instead of accumulating a Blob via 384 KB sudo calls.
- Newly managed data mounts request nosuid,nodev. Existing fstab entries are not rewritten.
- The storage detector recognises lsblk raid1/raid5/etc types.
- Restoring NAS display names merges existing names instead of wiping unrelated records.
- Browser-driven PiNAS updates now refresh all managed root helpers and the hostname/TLS listener, reducing helper-version drift.

## Interface

- Storage and share-onboarding guidance no longer describes released functionality as unfinished.
- Password dialogs preserve spaces and allow 256-character passwords; text dialogs still trim ordinary labels.
- Hostname preview updates while typing.
- Existing single-user private home shares are excluded from the MiniDLNA NAS-share preset list (manual media path edits still require operator care).
- MiniDLNA's advanced options are collapsed by default.
- Share editing offers an opt-in, password-protected repair for existing subfolders and files.
- Focus trapping is improved for the shared password/text dialog.

## TLS

PiNAS-generated self-signed certificates are marked as managed. After initial hostname setup or when a certificate is within 60 days of expiry, the root hostname helper can generate a new certificate with the configured hostname in its SAN and schedule a brief PiNAS restart. The monthly systemd timer checks for renewals. Existing unmarked custom certificates are not replaced; only the identifiable historical PiNAS default self-signed certificate may be adopted. Trust warnings for self-signed certificates remain normal.

## Tests and release validation

CI runs a targeted Ruff correctness check, Python compilation, JavaScript syntax, regression tests and a full byte-for-byte standalone release check. Legacy tests for removed helper names are replaced with tests against active helpers. The README module inventory is updated.

On a Raspberry Pi, test non-disruptive updates, certificates after first-run hostname setup, sleep-state drives, manual/automatic apt overlap, private share isolation, large SMB folders, ACL repair, large downloads and the WebUI updater's complete helper refresh before promoting the release.

## Deferred, separately scoped work

The following are intentionally not bundled into this security-hardening update:

- Moving all escaped helper string source into independent, lintable helper modules, which requires a coordinated build/test refactor.
- A secure NAS user-deletion workflow with share dependency checks and UID ownership handling.
- Replacing all native alert/confirm dialogs and trapping focus in every legacy modal.
- Consolidating all legacy CSS hover rules.
- Replacing the existing version-specific publish workflows with one unified tag-triggered release workflow.

These are structural changes and should not be conflated with immediate fixes to privilege and data-safety behaviour.
