# PiNAS v1.2.1 — Login Password Visibility

This lightweight patch adds a **show / hide password** eye button to the PiNAS login form.

## Change
- A compact eye icon sits **inside the right side of the password input** on the login page; clicking it reveals the current password and clicking again masks it.
- The same behaviour is available during first-run administrator setup, where the primary password field is shared with the sign-in form.
- The button starts in the **Show password** state with the input masked; while revealed it switches to the eye-with-slash icon and **Hide password** action.
- The toggle is a non-submit button (`type="button"`) with accessible labels, an `aria-pressed` state, explicit input association, keyboard focus styling and 42×42px touch target.
- The input retains its original value, password manager `autocomplete`, validation, login form submission and PiNAS authentication logic.
- Icons and hover/focus colours use the app’s existing light/dark theme tokens; no external assets or JavaScript packages are needed.

## Upgrade
From an existing PiNAS WebUI, go to **Settings → Update PiNAS** and upload the standalone `pinas.py` file for v1.2.1 once released. No changes to data disks, users, Samba shares, Linux ACLs, session management or system services are introduced.

## Verification
The regression suite checks the exact login markup, theme styling, accessible state, preservation of the input's password value, and show/hide transitions under Node.js. The existing JavaScript syntax test, generated bundle consistency, Python compilation and all earlier regression tests continue to apply.

**Release status:** patch candidate for review and hardware validation. PiNAS v1.2.0 remains the last published stable release until a separate v1.2.1 GitHub release is authorised.
