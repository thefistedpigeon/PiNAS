# PiNAS v1.1.0 — Media Server Release

PiNAS v1.1.0 is the first feature release following v1.0.0, bringing an **optional MiniDLNA/ReadyMedia server** to the lightweight Raspberry Pi NAS platform. MiniDLNA is installed on demand and is not required for the core NAS.

## Highlights

### Optional MiniDLNA Media Server
- Install, start, stop and restart MiniDLNA from the PiNAS web interface.
- Guided media-library setup creates `pinas-media/Movies`, `Television`, `Music` and `Pictures` on a selected mounted PiNAS data disk. Existing files are not deleted.
- Configure media folders and common DLNA preferences. Advanced MiniDLNA settings remain collapsed by default.
- Explicitly grant the MiniDLNA service read/traverse access to configured folders and their existing contents. New content can inherit default ACLs.
- Restart scanning or rebuild the media index without modifying the underlying media files.
- Administrators can upload media directly to a configured folder using a browser file picker. Multiple files, progress reporting and cancellation are supported. Files transfer in 384 KiB chunks, with private temporary staging, checks for filename/extension and size (maximum 100 GiB per file), no-clobber publication, and read-only MiniDLNA access for completed files.

### Storage diagnostics and disk health
- A separate manual **File Type Scan** for each configured mounted PiNAS data volume on the Storage page. It categorises allocated file blocks as Video, Pictures, Music or Other / filesystem and shows remaining free space.
- Background, metadata-only scanning avoids following symlinks or crossing other mounted filesystems. A restricted privileged helper can examine private root-owned shares without changing their access rights.
- More informative disk SMART health status (including standby/unsupported/USB adapter limitations), on-demand checks that avoid intentionally waking sleeping drives.
- Overview retains its lightweight used/free storage summaries.

### Administration, reliability and UI
- Administrator-only **Restart** and **Shutdown** actions with password confirmation and a short systemd-scheduled delay.
- New action SVG icons and consistent accent hover styling across Storage and Media Server buttons.
- A safer installer/updater refreshes managed privileged helpers. Additional hardening covers configuration and APT caching, noninteractive APT upgrades, sudoers validation, Samba share operation locking, TLS certificate handling, directory pagination, file-download streaming, and background jobs for longer operations.
- Improved Samba share inheritance and optional repair of access for existing files and directories.

## Installation and updates

Download **`pinas.py`** from this release's Assets, along with **`pinas.py.sha256`**.

Fresh install on Raspberry Pi OS Lite / supported Debian-based systems:

```bash
sudo python3 pinas.py --install --lan
```

To update an existing PiNAS appliance, open **Settings → Update PiNAS**, upload the trusted release `pinas.py`, and approve the update. Alternatively, install from the command line:

```bash
sudo python3 pinas.py --install --lan --skip-packages
```

Do not use `--skip-packages` if required OS packages are missing. Verify a downloaded asset with `sha256sum -c pinas.py.sha256` when both files are in the same directory. SHA-256 checks integrity, not publisher authenticity.

## Important notes

- PiNAS continues to target the Raspberry Pi 3B and newer, with low background CPU, memory and disk-I/O use. Docker/containers and heavyweight media libraries are deliberately outside the product scope.
- **MiniDLNA is optional.** It advertises media on the LAN; DLNA clients do **not** authenticate with individual SMB account credentials. Only expose media folders intended for your trusted local network.
- Browser uploads and scans may take longer on a Pi 3B or with large numbers of files. Existing SMB permissions should be tested, particularly where private shares or ACLs are in use.
- SMART data may be unavailable behind some USB-to-SATA bridges; such drives cannot be forced to provide missing data.
- Reboot/shutdown disconnects active users and interrupts transfers.
- PiNAS does not replace a backup. Test changes to mounting, permissions and filesystems before entrusting irreplaceable files to the device.

## Verification

The publication workflow requires the exact `1.1.0` source and bundle versions, release notes, byte-for-byte standalone rebuild equivalence, Python compilation, regression tests and targeted Ruff checks. Publication attaches the unmodified generated `pinas.py` and SHA-256 checksum under the immutable `v1.1.0` tag.

This release consolidates the changes developed in the v1.0.9–v1.0.17 milestones; the last published GitHub release before v1.1.0 was v1.0.8.
