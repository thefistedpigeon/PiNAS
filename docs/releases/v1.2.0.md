# PiNAS v1.2.0 — Official Release

PiNAS **v1.2.0** consolidates the tested v1.1.1–v1.1.4 improvements into a single, self-contained release for Raspberry Pi OS Lite, Raspberry Pi 3B/3B+ and newer. It retains the lightweight, NAS-focused design of v1.0: no containers, heavyweight media applications or continuously running monitoring agents.

## Highlights

### Storage and service monitoring
- The **Overview** and **Storage** pages automatically check supported disks' SMART status and temperature when opened and every ten minutes while displayed. The existing SMART helper avoids deliberately waking sleeping drives. Some USB bridges do not provide SMART telemetry.
- Overview includes storage usage, CPU, memory, temperature, NAS service health and the simplified automatic-update service state, **Last run succeeded**.
- RAID1 remains available when eligible disks are attached; an existing RAID array remains accessible for monitoring even if degraded. Destructive RAID creation is not enabled in this release.
- Storage retains the opt-in, per-volume **File Type Scan**.

### Share access and account administration
- **Samba share permissions and Linux POSIX ACLs are synchronised** on share creation and edits, with explicit read-only/read-write users and inheritance for new files. Changes to existing files and folders are reconciled; a **Repair Access** operation is available.
- NAS account creation can include a private home share under `pinas-shares/<username>` on an eligible mounted disk.
- Users can remove managed NAS accounts and secondary PiNAS administrators after re-authentication and exact-name confirmation. Active sessions are revoked. NAS users still assigned to SMB shares cannot be removed until share access is adjusted. Files and folders are preserved when removing a user.
- **Stop Sharing** removes managed network sharing without deleting data. **Delete Folder** is a separate irreversible action that requires explicit confirmation and re-authentication, and is restricted to a verified PiNAS-managed folder on an approved mounted data disk. Keep a backup.
- The Shares page uses consistent icon-and-text actions in this order: **Edit Share | Stop Sharing | Repair Access | Delete Folder**, alongside **Create Share** and a separate legacy folder-migration action when applicable.

### Updates, logs and session behaviour
- The idle timeout now respects the configured **5, 10, 15, 30 or 60 minutes**, without being extended by background polling; the browser automatically returns to login upon expiration.
- Manual and scheduled APT installations are recorded in a separate SQLite history database. Retention is selectable from **1–52 weeks** (default **12 weeks**).
- History appears as expandable, date-only records showing package names and the APT summary. **Download Logs** exports all retained records to a local text file.
- Check for updates includes supported Raspberry Pi firmware checks; automatic APT upgrades and reboot notices remain available.

### UI, media and packaging
- **Intel Clear Sans** is embedded for the main interface, and **Adobe Source Code Pro** for console/log-style text; both are served locally. No client font installation or internet connectivity is needed for the interface fonts. Licence notices are included.
- Light and dark themes, responsive layouts, consistent control styling and the existing Settings interface are retained.
- The optional lightweight **MiniDLNA/ReadyMedia** add-on and media-library tools from v1.1.0 remain available.
- Release is supplied as **one standalone `pinas.py` file** plus a `pinas.py.sha256` checksum. The GitHub Release is tagged **v1.2.0**.

## Download and install

Download `pinas.py` and `pinas.py.sha256` from this release's **Assets**.

For a fresh install on supported Raspberry Pi OS Lite / Debian systems:

```bash
sudo python3 pinas.py --install --lan
```

For an existing PiNAS installation, open **Settings → Update PiNAS**, upload the downloaded `pinas.py`, and approve the upgrade. The managed service and restricted helpers are updated as part of the installer process.

An alternative command-line upgrade is:

```bash
sudo python3 pinas.py --install --lan --skip-packages
```

Only use `--skip-packages` if all required system packages are already installed. Verify the local download when both assets are present:

```bash
sha256sum -c pinas.py.sha256
```

The checksum checks file integrity, not publisher authenticity; obtain the file from this repository's official release.

## Data safety and limitations

- PiNAS does **not** delete existing shares or data during the v1.2.0 application upgrade. **Delete Folder** is a separate, explicit action that irreversibly removes data.
- Share ACL reconciliation can take time on large filesystems and should be tested with existing Windows/Linux SMB clients before broad deployment.
- MiniDLNA broadcasts selected media to devices on the local network without per-user SMB authentication; grant access only to content meant for the trusted LAN.
- SMART temperature and status depend on support from each disk and its USB adapter.
- The project does not replace independent backups; RAID1 is not a backup.
- A full automated regression pass verifies the standalone bundle and core safeguards, but device-level Samba, USB SMART and disk behaviour should also be checked on representative Raspberry Pi hardware.

## Verification

The release workflow requires both modular source and generated `pinas.py` to contain version **1.2.0**, validates byte-for-byte bundle reproducibility, compiles the Python sources, checks critical Ruff rules, and runs the full regression suite. The release job publishes the validated standalone file and SHA-256 checksum against an immutable `v1.2.0` tag and verifies both attached assets.

The latest previously **published** GitHub Release was v1.1.0. This release consolidates the subsequent v1.1.1–v1.1.4 work that was iterated through pull requests and standalone builds.
